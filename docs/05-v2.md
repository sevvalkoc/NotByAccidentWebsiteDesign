# 05 · v2: what changed, and how to check it

v1 was not approved. v2 revises it rather than starting over: the same project, routes, facts and stack, made quieter, more visual and fully editable. The previous website (`NotByAccidentWebsiteDesign`) was not touched; its git history is unchanged. The full critique of v1 is in `04-v2-audit.md`.

## Measured against the brief

Homepage, English, prerendered HTML inside `<main>`, v1 (`2d3698e`) against v2 (built the same way, from the same static seed):

| | v1 | v2 | change | target |
|---|---:|---:|---:|---|
| Words | 611 | 312 | −49% | 50% less text-heavy |
| Images and videos | 6 | 9 | +50% | 40% more visual |
| Links to individual capabilities | 30 | 0 | −100% | 70% less capability-heavy |
| Homepage sections | 7 chapters, incl. a 30-item capability map | 7, incl. 5 practice areas | | 3–5 practice areas |
| Logo | full-bleed, masked, used as a section transition | 104–120px header lockup, 96px footer wordmark | | 90–160px |
| Largest type | `--t-mega` | `--t-display`, max ≈ 6.5rem, twice on the homepage | | ≈ `clamp(3rem, 6vw, 7rem)` |

"Quieter" isn't a number. What changed: no rotating words, no oversized statement, no logo masks, fewer labels and counters, one accent per view, and one signature interaction instead of several.

## Design

- **Palette**: void, graphite, frost, mineral, cool and silver as grounds; signal (periwinkle) as the digital accent; acid for one number that matters; beet, inherited from the first system, as the warm interrupt, used once on the 404 page. No gradients, no neon, no AI purple.
- **Environments**: sections are zones (`void`, `frost`, `mineral`, `cool`, `signal`, `beet`). The page's colours are registered custom properties, so scrolling from one zone into the next shifts the whole page instead of cutting. The prerender sets the opening environment on `<body>`.
- **Type scale**: micro, caption, small, body, lead, title, section, page, display. DM Sans throughout; Lora italic only for one emphasised word, written `*word*` in the CMS.
- **The slip** (signature interaction, order → interruption → order): media is built from five horizontal bands of the same image. On hover, focus or arrival the bands jump out of register by a few percent and settle back one after another. The offsets are fixed, so the accident is designed. The type version runs on the practice list. No glitch, noise or RGB split.
- **Other interactions**: environment shifts, sheet page transitions (View Transitions), quiet arrivals. All of them stop under `prefers-reduced-motion`.
- **Homepage**: hero (metadata, one headline, a living image, one line, two CTAs) → selected work (four projects in varied compositions) → five practice areas, linking to `/capabilities#group` → proof (one testimonial and three figures from the selected work) → studio → three notes with thumbnails → contact.
- **/capabilities**: the detail moved here, as five groups that open in place (native `<details>`; a `#group` link opens its group).

## CMS

Everything on the new site that's content is editable at `/admin`, and every Save writes to Supabase:

| Admin screen | Edits |
|---|---|
| **Homepage** | Hero (eyebrow, headline, line, both CTAs, image upload, video URL); Selected work (heading, CTA, project picker 3–5, ordered); Practice areas (up to 5: group, label, line); Proof (testimonial picker); Studio (copy, image, video); Featured notes (picker, ordered); Contact (heading, line, CTA); visibility per section; SEO card |
| **Pages** | Every other page (Work, Case studies, Capabilities, Studio, Notes, Trainings, Reports, Contact, Privacy, Cookies, 404): headers, sections, list items, images; SEO card per page |
| **Global** | Header menu, footer menu, footer copy and last line, announcement bar |
| Work | All fields incl. introduction, gallery (images and video), hero video URL, credits, external URL, status (draft/published/archived), order, featured, SEO, social title, description and image, canonical, noindex |
| Capabilities | All fields, visibility, order, SEO title and description, canonical, social image, noindex |
| Notes | Block editor, tags, status, SEO (unchanged from v1) |
| Footer / Contact | Emails, phone, hours, address, socials |
| Brand Settings / SEO | Logo, favicon, default OG image; site-wide SEO defaults, redirects |

The SEO card has: SEO title, meta description (with live character counts), social title, social description, social image, canonical URL, and noindex. A noindexed page keeps `noindex, follow` and leaves the sitemap.

**Previous site**: its page editor stays available as *Previous site: pages* and edits only its own slugs. The new site's pages live under `next/*` slugs in the same `pages` / `page_sections` tables, so the two sites can share one Supabase project without touching each other's content. Menus are stored as `next/global` sections rather than in `navigation_items`, which the live previous site reads.

### Migration 0010

`supabase/migrations/0010_next_site.sql`, generated from `src/content/sections.en.ts` by `node scripts/generate-next-seed.ts`. Idempotent (`if not exists`, `on conflict do nothing`), so it never overwrites an edit. It:

- creates `category_meta` (no earlier migration did, though the admin already used it) with RLS and its five rows;
- adds `og_title` / `og_description` to `pages`, `projects` and `articles`; `hero_video_url` to `projects`; `seo_title`, `seo_description`, `og_media_id`, `canonical_url` and `noindex` to `capabilities`;
- seeds the `next/*` pages, their sections and the external media they reference.

Also fixed: `0002_seed.sql` had a stray `;` before an `on conflict` clause that stopped a clean database from setting up.

### How content flows

Build: `scripts/cms-snapshot.ts` reads published content into `src/content/cms-snapshot.json`, and the prerender bakes it into static HTML, head included. Browser: after hydration the site fetches the same content live, so a Save shows up on the next page load without a rebuild. Search engines see the edit after the next deploy. Row-level security decides what an anonymous visitor can read: published work and notes, active capabilities, visible sections.

The CMS is authoritative: a field cleared in the admin stays cleared. Only a NULL (a field the database never had) falls back to the built-in default.

## Acceptance test (brief §43)

`scripts/cms-acceptance.mjs` runs all 18 steps in a real browser against a real database: the admin in one browser context, the public site in another, and the anonymous REST API for leak checks. Run against local Supabase (Supabase CLI, migrations 0001–0010) on 7 October 2026:

```
✓  1 Site runs
✓  2 /admin opens
✓  3 Sign in
✓  4 Change homepage hero text
✓  5 Save it
✓  6 Refresh the public homepage
✓  7 New hero text appears
✓  8 Change a homepage image (upload → Storage, file retrievable)
✓  9 Image updates publicly
✓ 10 Change a project title
✓ 11 Updates on listing and case study (/work, /case-studies, /, /case-studies/lavanta)
✓ 12 Change capability display information
✓ 13 Capability updates (/capabilities, /capabilities/brand-strategy)
✓ 14 Change footer contact information
✓ 15 Contact updates everywhere (/, /contact, /studio, /work)
✓ 16 Change SEO metadata
✓ 17 Page <head> updates (title, description, og:title)
✓ 18 Draft items do not leak (REST, /work, /case-studies, /search, its own URL)
All 18 steps passed
```

A rebuild afterwards carried every edit into the static HTML (`<title>`, meta description, `og:title`, hero, project title, contact email), and the draft did not appear in the sitemap or as a page.

Bugs the test found and v2 fixes: the public site's unlayered element styles and its generic `.block` / `.grid` classes were overriding the admin's Tailwind utilities, which collapsed grids and washed out inputs. Public base styles now sit in a cascade layer, `.block` became `.band` and the unused `.grid` was removed. Admin field hints sat inside `<label>`, which polluted accessible names; they now sit outside it.

## QA

- `pnpm typecheck`: clean.
- SEO audit: 177 pages, 7302 internal links, 603 JSON-LD blocks, 0 problems (unique titles and descriptions, one H1, canonical, hreflang, OG and Twitter tags, no broken internal links).
- axe-core: 0 violations on 15 representative pages, plus the 404s. Fixed on the way: the signal environment's tertiary text was 4.45:1 (now ≥ 4.5), the footer nav shared the header's label, and a nested `<aside>` on /capabilities.
- Responsive: 12 pages × 375/430/768/1024/1440/1728, with no horizontal overflow and no console or hydration errors. `/an-accident` correctly returns 404. Fixed: the tablet hero image pushed the statement below the fold; the slip showed hairline seams between bands at rest.
- Performance: no WebGL, no animation library. Slip bands share one image request. Videos load `preload="metadata"`.

## Honest limits

- The NL and FR versions read their own static copy; the CMS edits English (as in v1). Their structure mirrors the English sections, so per-locale CMS fields are a straightforward next step.
- Page-level section *order* is fixed by design on each template; the admin edits content and visibility, not layout.
- Imagery is still the placeholder photography the current site uses. The layouts are built for real project media, and the slip especially comes alive with real photographs.
- The sandbox couldn't reach Unsplash or the production Supabase, so screenshots use stand-in images, and the acceptance test ran on a local copy of the schema.
- Brief vs guidelines: the brand guideline PDF shows the logo large; the v2 brief caps it at 90–160px. The brief wins here and the guideline sizes are left for print.
